<DeskContext question={"Roll the whole book up to USD and prove nothing was double-converted."}>

The base book now contains both bonds, two cash deposits, the payer swap, equity option and CDS. Every holding must price before a total is meaningful. The term loan joins in lesson 4.3; credit and volatility specialization holdings enter later. This lesson keeps an audit trail from instrument currency to entity subtotal to the USD total, then reconciles risk and projected cashflows independently.

</DeskContext>

<Standard>

A position consists of a contract, quantity, entity and valuation date. The quantity is a count of the complete fixture contract: a one-unit USD corporate bond already contains USD 2 million notional. Multiplying by that notional again would overstate every result. `Portfolio.from_spec` validates the complete serialized positions. `value_portfolio` returns `PortfolioValuation`; aggregate metrics separately, and only then construct a `PortfolioResult` reporting envelope if required.

Keep native currency values intact until the declared reporting conversion. With EURUSD quoted as USD per EUR, $V_{USD}=V_{USD,native}+1.08V_{EUR,native}$. Sum decimal strings from serialized Money; converting through binary floats first discards the exact reporting representation. Pricing algorithms still use the recorded numeric mode, so exact storage does not imply exact analytical pricing. The reconciliation allowance here is one reporting cent for aggregation/rounding, not a percentage-of-NAV materiality threshold.

Risk measures need more identity than their short family names. `dv01::USD-OIS`, `pv01::USD-SOFR-3M` and `cs01::ACME-HZD` describe different factors. Preserve the curve and tenor in each key. A currency conversion changes monetary units but does not turn EUR rate risk into USD rate risk. The signed finite-difference DV01 convention is PV after a positive one-basis-point bump minus PV before it; a long fixed bond usually has negative signed DV01. If a desk reports positive-loss DV01, label the sign reversal explicitly.

Projected cashflows are a separate object from discounted value. Net only matching dates and currencies, retain each position's representation, and distinguish contractual payments from modeled or contingent amounts. A projected option cashflow representation must not be treated as a guaranteed receipt. Strict risk calculation and explicit applicability checks distinguish an inapplicable measure from a missing required result.

Materialization caches retain decoded contracts by content identity. They save repeated decoding, not valuation under a changed market. A fresh market or scenario still requires repricing. We check cache hit counts and unchanged decoded contracts rather than claim a speedup from a single noisy timing.

</Standard>

<BuildIt>

### Price, preserve currencies and reconcile

The factory creates a new seven-position book and a calibrated market. Request the declared risk families with strict calculation, verify applicability per position, then inspect every aggregated key. Both native and USD subtotals are retained. The two independent totals—summing base-currency positions and converting native-currency subtotals—must agree with the reported total within USD 0.01.

{/* notebook-block notebook="05_portfolio/portfolio_construction_and_valuation.ipynb" cell="base-book-reconciliation" role="build" */}
```python exec id=base-book-reconciliation role=build
from datetime import date
import json
from decimal import Decimal

from _shared.analyst_book import build_book, build_market, expected_metrics
from finstack_quant.portfolio import aggregate_full_cashflows, aggregate_metrics, value_portfolio
AS_OF = date(2025, 1, 15)

book, market = build_book("base"), build_market("base")
metric_applicability = expected_metrics('base')
requested_metrics = sorted({metric for families in metric_applicability.values() for metric in families})
print('Requested metric families:', requested_metrics)
valuation = value_portfolio(book, market, strict_risk=True, metrics=requested_metrics)
wire = json.loads(valuation.to_json())
currency_subtotals = {}
base_sum = Decimal("0")
for position_id, position in wire["position_values"].items():
    measures = position["valuation_result"]["measures"]
    for family in metric_applicability[position_id]:
        pass
    native = position["value_native"]
    amount = Decimal(native["amount"])
    currency_subtotals[native["currency"]] = currency_subtotals.get(native["currency"], Decimal("0")) + amount
    base_sum += Decimal(position["value_base"]["amount"])
total = Decimal(wire["total_base_currency"]["amount"])
fx_total = currency_subtotals["USD"] + currency_subtotals["EUR"] * Decimal("1.08")
print("Native currency subtotals:", currency_subtotals)
print("USD total:", total)
aggregated = aggregate_metrics(valuation, "USD", market, AS_OF)
print("Selected qualified aggregate metrics:", {key: value for key, value in sorted(aggregated.aggregated.items()) if key.startswith(("cs01::", "pv01::", "dv01::"))})
print("Complete qualified key count:", len(aggregated.aggregated))
ladder = aggregate_full_cashflows(book, market, allow_partial=False)
flows = json.loads(ladder.to_json())
print("Cashflow representations:", {key: value["representation"] for key, value in flows["position_summaries"].items()})
for currency in ["USD", "EUR"]:
    exact = sum(Decimal(event["amount"]["amount"]) for event in flows["events"] if event["amount"]["currency"] == currency)
    reported = sum(Decimal(str(amount)) for _, amount in ladder.net_in_currency_by_date(currency))
    print(currency, "first five ladder dates:", ladder.net_in_currency_by_date(currency)[:5])
again = json.loads(value_portfolio(build_book("base"), build_market("base"), strict_risk=True, metrics=requested_metrics).to_json())
for key in wire["position_values"]:
    pass
print("Fresh-factory repeated-run monetary and risk equality passed.")
```

### Inspect result stamps and materialization

The generated envelope records numeric mode and rounding metadata. The visible reporting policy separately states the dated FX conversion used above; do not infer a configurable FX policy stamp that this valuation result does not expose. Constructing an unrelated configuration object would not alter this pricing call.

<CheckYourself>

- Does an aggregate PV prove complete pricing? No: inspect degraded positions, risk completeness and expected applicability first.
- Can you sum coupon amounts and compare them directly with PV? No: currencies, payment dates, discounting and contingencies differ.
- Is a warm decoded contract a cached scenario value? No. Reprice after changing market inputs.
- What is exact in the repeated-run test? The serialized monetary results and calculated risk measures for identical inputs, excluding runtime timing metadata.
