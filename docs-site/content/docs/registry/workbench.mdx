The workbench installs into the host application. One shared browser worker validates
and prices the request. Amounts remain decimal strings while editing; results retain
the last completed request until a new valuation succeeds. The catalogue supports every discovered instrument. Open a [canonical example](/docs/registry/instruments), select its model and supply its complete market. Market Edit mode validates complete snapshots natively before repricing; View links the stored-node table and chart. Cashflows retain original native text, including mixed currencies; unsupported exports leave successful pricing intact. Detail views preserve metadata and bigint seeds, with raw JSON for incompletely declared payloads.

## Install locally

Build the optimized WASM package and registry from a checkout with the pinned tools:

```sh
mise run wasm-pkg
mise run ui-build
mise exec -- node finstack-quant-ui/scripts/install-local.mjs /absolute/path/to/next-app
```

Configure the Next app with Tailwind v4, a `components.json` using the `@finstack`
registry, and source aliases. The local installer serves built registry JSON over
HTTP and resolves the unpublished WASM dependency to an absolute local package path.
It disables dependency lifecycle builds so installation preserves the optimized artifact.
Published registry JSON is served under `/r/`; the npm WASM release is still pending.

Import `styles/finstack/theme.css` after Tailwind and mount `PricingWorkbench` inside
`FinstackQueryProvider`. Applications with an existing Query provider may use
`FinstackProvider` directly. Keep the installed workers, hooks and component paths together.

## Calibration and market views

The Calibrate tab imports complete canonical calibration envelopes. Static diagnostics
retain native dependency errors; a solve runs on submission. Select a returned step
for its linked residual table and chart. Use calibrated market validates the returned
market and updates the editor and pricing together. An edited envelope must be solved
again before its result can replace the market. Native solver failures remain visible
with their structured fields and any available diagnostics.

This demo explicitly supplies illustrative view inputs: surface extent 0–1, cube
absolute strike 0.05 with normal extent 0–0.1 and lognormal extent 0–2, and one FX
coordinate (expiry 1 year, strike 1.1, forward 1.12). These are demo inputs, not
recommended market parameters. Applications supply their own `surfaceOptions`,
`cubeOptions` and `fxOptions`; omitting them keeps stored data available. Optional
`scenario` inputs specify the native tranche ID, grid JSON and price extent for
structured-credit detail views. Registry checks preserve native output and do not
certify the upstream diagnostic quote association or deferred quote-space fits.
