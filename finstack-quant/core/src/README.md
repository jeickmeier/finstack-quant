# Core source organization

Core owns shared financial primitives, validated market-data artifacts, and
general numerical routines. It has no production dependency on another workspace
crate. Model evaluation and calibration methodology belong to their domain crates.

Use the [crate guide](../README.md) for public API guidance and rustdoc for symbol
signatures. This guide records placement rules rather than duplicating an API
inventory. Public module declarations and re-exports are in [lib.rs](lib.rs).

## Placement and boundaries

| Location | Responsibility |
|---|---|
| [dates/](dates/mod.rs) | Calendars, day counts, tenors, schedules, and fiscal/calendar periods. Public date types are re-exported through this facade. |
| [money/](money/mod.rs) and [currency.rs](currency.rs) | Decimal-backed money, rounding, currency metadata, and FX providers. |
| [market_data/](market_data/mod.rs) | Validated curves, quote grids, scalar observations, context storage, and scenario vocabulary. |
| [math/](math/mod.rs) | General numerical kernels, interpolation, solvers, statistics, and seeded random generators. |
| [cashflow/](cashflow/mod.rs) | Foundational flows, discounting, and IRR calculations. Instrument cashflow construction belongs in the cashflows crate. |
| [expr/](expr/mod.rs) | Array expression AST, DAG compilation, and evaluation; period-aware statement evaluation belongs in statements. |
| [types/](types/mod.rs) | Identifiers, rates, ratings, attributes, and shared taxonomies. |
| [contract/](contract/mod.rs), [canonical.rs](canonical.rs), [wire.rs](wire.rs) | Load limits/diagnostics, canonical bytes, and explicit wire representations. |
| [schema/](schema/mod.rs) | Schema assembly, registry, externalization, and projection, gated by `json-schema`. |
| [config.rs](config.rs), [error/](error/mod.rs), [explain.rs](explain.rs) | Caller-supplied policies, shared errors, and opt-in calculation traces. |
| [embedded_registry.rs](embedded_registry.rs), [rating_scales.rs](rating_scales.rs) | Shared public registry loader and neutral credit-rating scales. |
| [table.rs](table.rs) | Serializable columnar interchange; Arrow conversion belongs in arrow-interchange. |

A public facade owns a concept's imports. Implementation children should be
private unless callers need to name the module itself. Do not create a second
implementation to avoid crossing a private module boundary; move the invariant
and expose the smallest internal operation needed by callers.

## Larger implementations

- [dates/schedule/](dates/schedule/mod.rs): public types in the facade,
  validated construction and payment/fixing adjustments in `builder.rs`,
  serializable input in `spec.rs`, and raw anchors in `generation.rs`.
- [dates/periods/](dates/periods/mod.rs): public period vocabulary and planning
  entry points in the facade, Gregorian/fiscal bounds in `calendar.rs`, and
  grammar/range stepping in `parse.rs`.
- [market_data/term_structures/](market_data/term_structures/mod.rs): each curve
  owns its representation, validation, evaluation, and transformations. The
  discount, forward, and hazard curve directories separate these concerns with
  private implementation files. Smaller curves remain cohesive single files.
- [market_data/bumps.rs](market_data/bumps.rs) owns specifications, units, IDs,
  and the `Bumpable` trait. Implementations live with their curve/scalar types.
  [context/](market_data/context/mod.rs) dispatches transformations and maintains
  stored IDs and dependent references; it does not recalculate curve-specific
  shocks. Direct and context entry points must apply identical financial rules.
- [market_data/surfaces/](market_data/surfaces/mod.rs) owns validated volatility
  artifacts. FX quote conversion, smile evaluation, and rectangular
  materialization share one implementation in models' volatility module.

Keep public imports stable when only moving private implementation files.
Changes to public ownership must update downstream Rust callers, bindings,
contract metadata, and documentation in the same change. Calibration model
version strings live in calibration alongside the methodologies they identify.

## Generated assets

[build.rs](../build.rs) derives calendars and SIFMA settlement tables into
`OUT_DIR`. Committed currency and Chinese New Year Rust tables are generated by
[generate_reference_data.py](../build/generate_reference_data.py) from the
maintained CSVs under `data/`. Run `mise run core-gen-data` to regenerate them
and `mise run core-check-data` to check without writing. `gen-write` and
`gen-check` include these operations.

[gen_lunar_festivals.py](../build/gen_lunar_festivals.py) separately refreshes
Dragon Boat and Mid-Autumn dates and their Rust tables using `lunar_python`.
[holiday_generated.rs](generated/holiday_generated.rs) contains the maintained
calendar coverage limits. Generated data changes require an explicit review of
the inputs; a refactor must not silently change holiday or currency values.

## Validation

Use `mise run rust-lint-crate -- finstack-quant-core` and
`mise run rust-test-crate -- finstack-quant-core` during iteration. The
[test guide](../tests/README.md) describes integration wiring; the
[benchmark guide](../benches/README.md) describes benchmark registration.
Run `mise run rust-doc` for documentation and doctests and
`mise run rust-check-schemas` for the persisted schema contract. The crate
README's Rust examples are included in doctests by `lib.rs`.
