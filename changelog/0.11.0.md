# Finstack Quant 0.11.0

**Release Date**: 2026-10-18

**Bump type**: minor (pre-1.0; intentional breaking Rust, Python, WASM, and JSON changes)
**Status**: Prepared, not yet tagged (`v0.7.0` is the latest git tag; `v0.8.0`, `v0.9.0`, and `v0.10.0` were never created)

## Executive Summary

0.11.0 splits the monolithic `finstack-quant-valuations` and
`finstack-quant-models` crates along their natural dependency boundaries so incremental
edits no longer rebuild the entire downstream graph, simplifies the `core`,
`scenarios`, and `attribution` APIs, and surfaces provenance and calculation
intermediates across valuation, cashflow, calibration, margin, attribution,
and statement results.

Callers on `v0.7.0` must apply
[`0.8.0.md`](0.8.0.md),
[`0.9.0.md`](0.9.0.md), and
[`0.10.0.md`](0.10.0.md) before this one. There is
no `v0.8.0`, `v0.9.0`, or `v0.10.0` tag.

The itemized history is under **Itemized changes** below.

## Who Should Upgrade

- Rust callers importing directly from `finstack-quant-models::factor`,
  `finstack-quant-valuations::instruments::rates::hw1f`, or the moved
  `cashflows` / `core` / `models` kernels, or implementing `Instrument` outside
  the workspace.
- Rust, Python, and WASM callers of `core` (`Percentage`, `Rate`, `Bps`,
  `Money`, `HolidayCalendar`, `DiscountCurve`, `FxMatrix`), `margin`,
  `scenarios`, `attribution`, or `calibration` touched by the breaking API and
  wire changes below.
- Callers consuming persisted `VmResult`, `CashflowRow`, or `QuoteQuality`
  payloads, which gain required fields or replace placeholder target/fitted
  columns with `quote_value`.

## Breaking Changes

### 1. Valuations and factor crate split

- **Factor crate (`finstack-quant-factor`)**: `finstack_quant_models::factor`
  is now the standalone `finstack-quant-factor` crate. The umbrella path
  `finstack_quant::models::factor` and the Python/WASM `models.factor`
  namespaces are unchanged. `finstack_quant_analytics::correlation` is removed;
  `nearest_correlation` and `NearestCorrelationOpts` live in
  `finstack_quant_core::math::linalg` (and remain re-exported at
  `finstack_quant_models::correlation`).
- **Valuations split (`finstack-quant-valuations-{core,rates,fixed-income,structured-credit,credit,equity,fx,exotics}`)**:
  `finstack-quant-valuations-core` holds the pricing framework (`Instrument`,
  `PricingOptions`, `PricerRegistry`, `Family`, `MetricId`, `ValuationResult`,
  conventions, and cashflow export). Each instrument family owns its
  registrations via a `Family` static (`RATES`, `FIXED_INCOME`,
  `STRUCTURED_CREDIT`, `CREDIT`, `EQUITY`, `FX`, `EXOTICS`), and
  `finstack-quant-calibration` depends only on `valuations-{core,rates,credit}`.
  The umbrella `finstack-quant-valuations` re-exports the framework and families
  at their previous paths.
- **Moved kernels**:
  - Hull-White 1F Monte Carlo and LSMC engines move from
    `finstack_quant_valuations::instruments::rates::hw1f` to
    `finstack_quant_models::rates::hw1f` (`Hw1fMcPricer`, `Hw1fLsmcPricer`,
    `Hw1fMcConfig`, `ShortRateBasis`).
  - `RateSpec` and `FloatingLegCompounding` live in
    `finstack_quant_cashflows::builder`.
  - Carr-Madan variance replication, the three-factor credit-line process
    (`CreditLineProcess`), `PiecewiseGbmProcess`, and the range-accrual /
    cliquet / autocallable payoffs move to `finstack-quant-models`.
  - Prepayment/default rate conversions (`clamped_cpr_to_smm`, `psa_to_cpr`, …)
    move to `finstack_quant_cashflows::builder`.
  - Curve-time, z-spread discount factor, compensated statistics, basis-point
    unit constants, FX spot-date helpers, and input validators move to
    `finstack-quant-core`.
- **Registry dispatch**: `PricingDispatch::from_model(model, registry)` takes
  the registry explicitly. Pricing with `PricingOptions::registry` unset
  resolves the instrument's `Instrument::family()` registry.

```rust
// Before (0.10.0)
use finstack_quant_models::factor::FactorModelConfig;
use finstack_quant_valuations::instruments::rates::hw1f::RateExoticMcConfig;

// After (0.11.0)
use finstack_quant_factor::FactorModelConfig;
use finstack_quant_models::rates::hw1f::Hw1fMcConfig;
```

### 2. Core, Margin, Scenarios, and Attribution API simplification

- **`Percentage` removed**: Use `Rate::from_percent` / `Rate::as_percent`.
  Python `Rate.as_percentage`, `Bps.as_percentage`, and
  `CreditRating.from_name` (use `CreditRating(name)`), and WASM `asPercentage` /
  `CreditRating.fromName`, are removed.
- **Exact decimal percent conversion and checked operators**:
  `Rate::from_percent`, `Rate::as_percent`, and `"%"` rate strings move the
  decimal point of the shortest decimal form (`from_percent(1.1)` is exactly
  110 bp). `Bps` and `Rate` arithmetic operators panic on overflow, zero
  divisor, or non-finite input in every build profile; Python and WASM
  `Bps.abs` raise on `i32::MIN`.
- **`Money` and `Id` cleanup**: `Money` removes `into_amount`, `into_parts`,
  `f64` `*`/`/` operators, `TryFrom<(f64, Currency)>`, and the `money!` macro.
  `Id::into_string` and `FromStr for Id` are removed.
- **`Discountable::npv` and `poisson_inverse_cdf`**: Both return `Result`
  (`PVOutput` associated type and the `λ > 30` normal approximation are
  removed).
- **Calendars and FX spot dates**: `HolidayCalendar::is_business_day` has no
  default implementation; `DateExt::is_business_day` is removed.
  `DiscountCurve` carries an optional `calendar_id` (required for `Bus/252`).
  `fx_spot_date` takes a `u32` contractual lag (0..=31) and requires a USD
  calendar for non-USD crosses. `FxMatrix::clear_cache` → `clear_quotes`,
  `cache_stats` → `stored_quote_count`.
- **Margin fallibility**: `ClearingHouseImCalculator::calculate_conservative`,
  `MarginFundingCost::calculate` / `cost_for_period`, and
  `Haircut01::calculate` return `Result` (raising `ValueError` in Python and
  throwing in WASM instead of returning `NaN`/`±∞`).
- **Scenarios and Attribution**:
  - `ScenarioSpec::with_hazard_bump_mode` is removed on every host; pass
    `hazard_bump_mode` to the constructor or set the field.
  - Python `ApplicationReport.warnings_json` and `HorizonResult.warnings_json`
    are removed (`warnings` returns the same list).
  - Rust `ScenarioSpec::parallel_bp_many` moves to
    `OperationSpec::parallel_bp_many`; `ScenarioEngine::recalibration_provider`
    → `get_recalibration_provider`.
  - Rust long-row attribution projections are imported from
    `finstack_quant_attribution::long_rows`.

### 3. Persisted wire and result changes

- **`QuoteQuality.quote_value`**: Replaces `target_value` and `fitted_value` on
  calibration quote reports and DataFrames (`quote_value` column replaces
  `target` and `fitted`). `CalibrationDiagnostics.singular_values` and
  `r_squared` are removed.
- **`VmResult`**: Gains required fields `threshold`, `independent_amount`,
  `collateral_balance`, `unrounded_call`, `mta`, and `rounding_increment`.
- **`CashflowRow`**: Requires `native_pv` on input and adds coupon-input and FX
  columns (`accrual_start`, `accrual_end`, `accrual_day_count`,
  `accrual_notional`, `index_rate`, `principal_delta`, `native_pv`, `fx_rate`).

## New Features and Improvements

- **Valuation provenance and explain traces**: Every `ValuationResult` carries
  `provenance` (`ValuationProvenance`: model, `requested_as_of`, declared
  `market_dependencies`, `scenario_price_shock_decimal`, and effective
  `sensitivity_bumps`). `PricingOptions::with_explain(ExplainOpts)` (Python
  `price_instrument(..., explain=True)`, WASM trailing `explain` boolean)
  attaches a per-cashflow PV trace under discounting and hazard-rate models.
- **Calibration explain traces and curve provenance**: `CalibrationConfig.explain`
  is now a wire setting (`{"explain": {"enabled": true}}`), recording
  `knot_solved` and `global_solve` steps. Python and WASM expose
  `DiscountCurve.rate_calibration`, `ForwardCurve.rate_calibration`, and
  `HazardCurve.hazard_calibration`.
- **Rich intermediate result fields across domains**:
  - Margin: `ImResult.simm_detail`, `XvaResult.{cva_rows,dva_rows,fva_rows}`,
    `FrtbSbaResult.scenario_breakdown`.
  - Portfolio margin bindings: Python `portfolio.PortfolioMarginAggregator`,
    `PortfolioMarginResult`, `NettingSetMargin`; WASM
    `portfolio.PortfolioMarginAggregator`.
  - Attribution: `PnlAttribution.{pv_t0,pv_t1}`, `waterfall_steps`, and
    `sensitivity_steps`.
  - Statements & analytics: `StatementResult.node_sources` / `get_source`,
    `CheckFinding.comparison`, principal prepayment breakdown on
    `CashflowBreakdown`, `CorporateValuationResult` DCF bridge fields, and
    `GoalSeekResult` convergence diagnostics.
  - Scenarios & portfolio: `ApplicationReport.applied_shocks` and
    `PositionValue.{fx_rate,fx_triangulated}`.
- **Market conventions**: Added `AUD-BBSW-3M` and `AUD-BBSW-6M` rate indices;
  USD/PHP and USD/RUB T+1 spot pairs; Zurich (`chzh`), SIX (`six`), and `defr`
  weekend holiday rules updated.

## Bug Fixes

- `Explanation.breakdown` is now empty when a statement cell's value came from
  an explicit value, forecast, or `where` mask rather than evaluating its
  formula.
- Expression engine `rank` assigns minimum rank (`method="min"`) to tied
  values, matching its documentation and statement semantics.
- Curve-shift measurements in `market_data::diff` return an error on an empty
  or non-finite tenor grid or sample instead of averaging over fewer curves.
- Rolled basis-spread, inflation, and price curves preserve their source
  interpolation (`roll_transform`) when shocked after rolling.

## Deprecated

None. Removed names are deleted with no compatibility aliases.

Removed unused dependencies: `smallvec`, `thiserror`, and `tracing` from
`finstack-quant-valuations`; `rand` and `rand_pcg` from
`finstack-quant-models`; `finstack-quant-models` from
`finstack-quant-portfolio`; direct `rayon` from `finstack-quant-scenarios` and
`finstack-quant-attribution`. Upgraded `nalgebra` to `0.35` (`simba 0.10.2`) and
`rust_decimal` to `1.43.0`, eliminating `paste` (`RUSTSEC-2024-0436`) and
`rkyv` (`RUSTSEC-2026-0235`) from `Cargo.lock` and removing their advisory
ignores from `deny.toml` and `osv-scanner.toml`.

## Itemized changes

Workspace version 0.11.0: the valuations split below removes and moves public Rust items (see the section that follows), so the crates, the Python wheel and the WASM package take a breaking-change version bump.

### Dependencies

#### Changed

- Upgraded `nalgebra` from `0.34` to `0.35` (`simba` `0.10.2`) and `rust_decimal` from `1.41`/`1.42` to `1.43.0`, removing transitive `paste` (`RUSTSEC-2024-0436`) and optional `rkyv` (`RUSTSEC-2026-0235`) from `Cargo.lock` and dropping both advisory ignores from `deny.toml` and `osv-scanner.toml`.

#### Removed

- Unused `smallvec`, `thiserror` and `tracing` dependencies from `finstack-quant-valuations`.
- Unused `rand` and `rand_pcg` dependencies from `finstack-quant-models`.
- Unused `finstack-quant-models` dependency from `finstack-quant-portfolio`.

### Factor models are the `finstack-quant-factor` crate

#### Changed

- New crate `finstack-quant-factor` (`finstack-quant/factor`) holds what was `finstack_quant_models::factor`: factor definitions and matching, covariance, sensitivity matrices, risk decomposition and the hierarchical credit-factor calibrator. It depends on `finstack-quant-core` and `finstack-quant-analytics` (`beta`). `finstack-quant-models` no longer has a `factor` module and no longer depends on `finstack-quant-analytics`, so a factor or analytics edit no longer rebuilds valuations, calibration or statements. Rust callers that used `finstack_quant_models::factor::X` use `finstack_quant_factor::X`; the umbrella path `finstack_quant::models::factor::X` and the Python/WASM `models.factor` namespaces are unchanged.
- `gen_models_schemas` is a binary of the umbrella package (`cargo run -p finstack-quant --bin gen_models_schemas`); it still writes `finstack-quant/models/schemas`, whose paths and `$id`s are unchanged. The factor-owned models-family artifacts are `finstack_quant_factor::schema::MODELS_ARTIFACTS`. `description` text changes where rustdoc links named the old module path.
- The canonical factor fixtures moved from `finstack-quant/models/tests/data/canonical/` to `finstack-quant/factor/tests/data/canonical/`.

#### Removed

- `finstack_quant_analytics::correlation`. `nearest_correlation` and `NearestCorrelationOpts` moved to `finstack_quant_core::math::linalg`, beside `validate_correlation_matrix` and `CorrelationError` (which the analytics module only re-exported). `finstack_quant_models::correlation` re-exports all four, so the Python/WASM `models.correlation` namespace is unchanged.

The envelope schema marker `InstrumentSchema`, `MAX_JSON_BYTES` and the load-error mapping live in `finstack_quant_valuations_core::instruments::envelope` and the schema packager `package_valuations_schema` in `finstack_quant_valuations_core::schema`; the umbrella re-exports both at their previous paths.
- `finstack-quant-valuations-structured-credit` (`finstack-quant/valuations/structured-credit`): the structured-credit tier — `StructuredCredit`, `AgencyCmo` (with `CmoTranche`, `CmoTrancheType`, `CmoWaterfall`) and `AssetBackedFacility` with the `STRUCTURED_CREDIT` family static, as `finstack_quant_valuations_structured_credit::{structured_credit, cmo, asset_backed_facility}`; `data/assumptions/structured_credit_assumptions.v1.json` moves with the deal-type registry. - `finstack-quant-valuations-fixed-income` (`finstack-quant/valuations/fixed-income`): the fixed-income family — `Bond`, `BondFuture`, `ConvertibleBond`, `InflationLinkedBond`, `TermLoan`, `RevolvingCredit`, `FiIndexTotalReturnSwap`, `AgencyMbsPassthrough`, `AgencyTba`, `DollarRoll` with the `FIXED_INCOME` family static and the FI-TRS `Marginable` impl; `data/assumptions/tba_assumptions.v1.json` moves with the TBA pricer. Re-exported as `instruments::fixed_income`. `StructuredCredit`, `AgencyCmo` and `AssetBackedFacility` register with `STRUCTURED_CREDIT` instead of `FIXED_INCOME` (`Instrument::family()` follows); registered models and metrics per instrument type are unchanged. `instruments::fixed_income::bond_from_cashflows_json` (it builds an `InstrumentJson`) lives in the umbrella; the `fixed_income::bond::bond_from_cashflows_json` alias is gone. The engine entry points the structured-credit code reaches (`mbs_passthrough::{pricer, metrics::duration}`, `revolving_credit::pricing::{unified, path_generator}` and their items) are `#[doc(hidden)] pub`.
- `finstack-quant-valuations-rates` (`finstack-quant/valuations/rates`): the interest-rate and inflation family — `Deposit`, `ForwardRateAgreement`, `InterestRateFuture`, `InterestRateFutureOption`, `InterestRateSwap`, `BasisSwap`, `XccySwap`, `CapFloor`, `Swaption`, `BermudanSwaption`, `CmsSwap`, `CmsOption`, `CmsSpreadOption`, `Repo`, `InflationSwap`, `YoYInflationSwap`, `InflationCapFloor` with the `RATES` family static and the IRS/repo `Marginable` impls. Re-exported as `instruments::rates`. The listed-product terms (`ListedFutureTerms`, `FutureOptionTerms`, …) are now re-exported from `finstack_quant_valuations_core::instruments` as well as from the umbrella.

#### Changed

- New crate `finstack-quant-valuations-core` (`finstack-quant/valuations/core`) holds the pricing framework: the `Instrument` trait and its hooks, `PricingOptions` and the pricing overrides, the shared parameter types and kernels (`instruments::common_impl`, hidden), the per-flow cashflow exporter engine (`instruments::cashflow_export::export_cashflows`), `pricer::{InstrumentType, ModelKey, PricerKey, Pricer, PricerRegistry, PricingDispatch, Family, parse_model_key}`, the metric framework and universal calculators, `results`, `market`, `recalibration`, `constants`, `error` and the embedded conventions, contract specs, product defaults and listed-product catalog. `finstack-quant-valuations` depends on it and re-exports every item under its previous path (`finstack_quant_valuations::instruments::Instrument`, `::metrics::MetricId`, `::results::ValuationResult`, the exported macros, …), so downstream crates and the bindings are unchanged. The umbrella keeps the instrument families, `instruments::{json_loader, composite}`, `pricer::{json, FAMILIES, STANDARD, standard_pricer_registry}`, `metrics::standard_registry`, the JSON cashflow-export entry points, `schema` and the benches and integration tests.
- `metrics::standard_registry` is defined on the umbrella's `metrics` façade; the core's `metrics::core::universal` holds `register_universal_metrics`. `ShortRateTreeModel`, `StructuredCreditPricingMode`, `NdfQuoteConvention`, `ResettingSide` and `VolatilityModel` are no longer `#[non_exhaustive]`: the instrument families match them exhaustively from their own crate. The `FinancialBuilder` derive now emits `finstack_quant_valuations_core::instruments::Instrument::validate_invariants`.

### Instrument families own their registrations

#### Added

- `finstack_quant_valuations::pricer::Family`, the registration unit of the valuations stack. Each built-in family is a `static` beside its instruments — `instruments::rates::RATES`, `instruments::fixed_income::FIXED_INCOME`, `instruments::fixed_income::structured_credit::STRUCTURED_CREDIT`, `instruments::credit_derivatives::CREDIT`, `instruments::equity::EQUITY`, `instruments::fx::FX` and `instruments::exotics::EXOTICS` (which owns the commodity leaves) — whose `pricers()` and `metrics()` registries are built on first use. `pricer::FAMILIES` lists them; `pricer::STANDARD` merges them and adds `Composite` and `Basket`. `Instrument::family()` names an instrument's family (`impl_instrument_base!` now takes it as its second argument); the default, `Family::unregistered()`, registers no pricers and only the universal metrics.
- `Instrument::validate_cashflow_export(model)` and `Instrument::cashflow_export_terms(market, as_of)`, the hooks the per-flow cashflow exporter (`instruments::cashflow_export`, formerly re-exported from `common_impl`) decomposes an instrument with. `CashflowExportTerms` carries the schedule to export, per-currency discount curves, the reporting currency, pool paydown states (`CashflowPoolState`) and inflation index ratios. `Bond` rejects the export of embedded options and return floors; `FxSwap`, `XccySwap`, `AgencyMbsPassthrough` and `InflationLinkedBond` supply what the exporter used to obtain by downcasting. Exported rows are unchanged.

#### Changed

- The six `finstack_quant_margin::Marginable` impls (`InterestRateSwap`, `Repo`, `CreditDefaultSwap`, `CdsIndex`, `EquityTotalReturnSwap`, `FiIndexTotalReturnSwap`) live beside their instrument types (`<instrument>/marginable.rs`) instead of one `instruments/marginable.rs`; the shared helpers are `instruments::common_impl::margin`. Behaviour unchanged.
- `PricingDispatch::from_model(model, registry)` takes the registry the explicit model is resolved in instead of reaching for the standard one; the Python and WASM VaR entry points pass `STANDARD.shared_pricers()`.
- Pricing with `PricingOptions::registry` or `metric_registry` unset resolves the instrument's family registries instead of the merged standard ones. For every built-in instrument type the family registers the same models and metrics as the standard registry (`tests/registry_snapshot.rs` pins both), so results are unchanged. An `Instrument` implemented outside the crate now needs an explicit registry (or its own `value`) for registry pricing, where it previously failed the pricer's downcast.
- `standard_pricer_registry()` and `metrics::standard_registry()` return the `STANDARD` family's registries; the asset-class registration modules under `src/pricer/` are replaced by the family files. `XccySwap` registers with the rates family and `QuantoOption` with FX; the `ExpectedLoss` owner entry is registered by the family whose pricers publish it (`Bond` by fixed income, `StructuredCredit` by structured credit).

### Model kernels moved from valuations to `finstack-quant-models` and `finstack-quant-cashflows`

#### Changed

#### Changed

The old path is removed, not re-exported.
- `Hw1fMcConfig::default()` reads the new `rust.hw1f` block of the models Monte Carlo defaults registry (overridable through the `monte_carlo.defaults.v1` config extension); the `rate_exotics` block leaves the valuations product defaults. `Hw1fMcConfig::lmm_bermudan()` is replaced by `finstack_quant_valuations::instruments::rates::swaption::lmm_pricer::lmm_bermudan_mc_config()`.

### Core API simplification

#### Added

- `DiscountCurve` owns the holiday calendar of its time axis: `DiscountCurveBuilder::calendar_id` / `calendar_id_opt`, `DiscountCurve::calendar_id` and `day_count_context`, and the `Discounting::day_count_context` trait method. A Bus/252 curve counts business days on its own calendar in `df_between_dates`, `npv`, the `*_on_date` lookups and `roll_forward`, and is rejected at build without one. The wire form gains an optional `calendar_id`. Python `DiscountCurve(..., calendar_id=...)` and `.calendar_id`; WASM option `calendarId` and getter `calendarId`.
- `HolidayCalendar::calendar_id` (canonical registry id, including `+`-joined unions) and a blanket `impl HolidayCalendar for &T`.
- `Rate::try_from_bp`, `Div<f64> for Rate`, `TryFrom<f64> for Bps`, `Bps::checked_abs`, `PeriodId::shift`, `PeriodId::year`/`index`, `FiscalConfig::start_month`/`start_day`/`year_start`, `CFKind::LcFee` and `CFKind::FrontingFee` in the hosts.
- Rate-index registry entries `AUD-BBSW-3M` and `AUD-BBSW-6M` (T-0 fixing, ACT/365F, Sydney `auce` calendar, T+1 settlement).
- FX spot: USD/PHP and USD/RUB are T+1 pairs alongside USD/CAD and USD/TRY.

#### Changed (breaking)

- `HolidayCalendar::is_business_day` has no default; every calendar states its weekend rule. `DateExt::is_business_day` is removed. `DayCountContextState` converts from a `DayCountContext` with `TryFrom` and rejects a calendar with no registered id.
- `Discountable::npv` returns `Result<Money>` (the `PVOutput` associated type is removed).
- `Percentage` is removed on every host; use `Rate::from_percent` / `Rate::as_percent`. Python `Rate.as_percentage`, `Bps.as_percentage` and `CreditRating.from_name` (use `CreditRating(name)`), and WASM `asPercentage` / `CreditRating.fromName`, are removed.
- `Rate::from_percent`, `Rate::as_percent` and a `"%"` rate string move the decimal point of the shortest decimal form instead of dividing or multiplying in binary (`from_percent(1.1)` is exactly 110 bp). Results can differ from the previous values in the last bit.
- `Bps` and `Rate` operators panic on overflow, a zero divisor or a non-finite result in every build profile (the `checked_*` methods return the error). Python and WASM `Bps.abs` raise instead of panicking on `-2147483648` bp.
- `Money` loses `into_amount`, `into_parts`, the `f64` multiply/divide operators and their assign forms, `TryFrom<(f64, Currency)>` and the `money!` macro. `Id::into_string` and `FromStr for Id` are removed. `FactorId`, `NodeId`, `CovenantMetricId` and `RateCalibrationFutureContractId` are `Id<Tag>` aliases; their JSON is unchanged and their schemas reference the shared `Id` definition.
- `poisson_inverse_cdf` returns `Result<usize>` and is exact at every intensity (the normal approximation above an intensity of 30 is removed).
- Margin `ClearingHouseImCalculator::calculate_conservative`, `MarginFundingCost::calculate` / `cost_for_period` and `Haircut01::calculate` return `Result`; Python raises `ValueError` and WASM throws where they previously returned NaN or infinity.
- `fx_spot_date` takes a `u32` contractual lag (0 through 31) and requires a USD calendar for a non-USD cross. An explicit lag is honored in both directions: a T+1 tom-next EUR/USD trade settles the next joint business day, and a lag above the pair standard counts business days on each currency's calendar. Calendar-less FX instruments use `usny` for their USD leg.
- `FxMatrix::clear_cache` → `clear_quotes`, `cache_stats` → `stored_quote_count` (same behavior).
- `CFKind` `Display`/`FromStr` use the serde label (`"pre_payment"`, previously `"prepayment"`) and parse exactly.
- `MarketContextState` drops the `vol_index` curve variant: a vol-index curve is a `price` curve carrying `spot_level`. A calibration prior tagged `volatility_index_curve` must hold a vol-index curve, and `curve_counts` report such curves as `VolIndex`.
- Rolled basis-spread, inflation and price curves keep their source interpolation (`roll_transform` on the wire); a shock on a rolled curve shocks the source pillars and reads the current pillars back. `ParametricCurve` state carries `time_offset` (default `0`).
- `PeriodPlan` and `FiscalConfig` deny unknown fields; fiscal `next()`/`prev()` step across years instead of erroring.
- The expression engine's `rank` assigns tied values their minimum rank (pandas `method="min"`), matching its documentation and statements; it assigned dense ranks.
- Curve-shift measurements in `market_data::diff` return an error for an empty or non-finite tenor grid or sample; attribution propagates that error instead of averaging over fewer curves (a curve missing from either market is still skipped).
- Zurich (`chzh`), SIX (`six`) and `defr` calendars no longer move a weekend holiday to Monday.

### Export auditability

#### Added

- Every priced `ValuationResult` carries `provenance` (`ValuationProvenance`): the `model` that produced the value, the `requested_as_of` date (the result's `as_of` is the effective date after the instrument resolved it), the instrument's declared `market_dependencies`, the `scenario_price_shock_decimal` already applied to the value, and, when metrics are requested, `sensitivity_bumps` (`SensitivityBumps`: `rate_bump_bp`, `credit_spread_bump_bp`, `spot_bump_decimal`, `vol_bump_decimal`, optional `ytm_bump_bp`, `adaptive_bumps`) after layering the `valuations.sensitivities.v1` extension and the instrument's `bump_config`. Python `ValuationResult.provenance` returns the dict; WASM results carry the field.
- `PricingOptions::with_explain(ExplainOpts)` attaches a step trace to `ValuationResult.explanation`. Under `discounting` and `hazard_rate` it holds one `cashflow_pv` entry per projected cashflow, built from the same rows as `instrument_cashflows` and reconciled to the value; under any other model it holds one `computation_step` entry named `cashflow_trace_unavailable` with the reason. Python `price_instrument(..., explain=True)`; WASM `priceInstrument` and `priceInstrumentWithMarket` take a trailing `explain` boolean. The typed instrument `price` methods do not take it; pass the instrument to `price_instrument`.
- `TraceEntry::CashflowPV.survival_probability` (conditional survival to the payment date, hazard-rate valuations only).
- `CashflowRow` carries the inputs of each coupon and the pre-conversion value: `accrual_start`, `accrual_end`, `accrual_day_count`, `accrual_notional` (outstanding principal at accrual start), `index_rate` (floating index before spread, gearing, caps and floors), `principal_delta`, `native_pv` (row currency, before FX and scenario shock) and `fx_rate` (reporting currency per unit of row currency). `InstrumentCashflowEnvelope.scenario_price_shock_decimal` records the shock applied to every row `pv`. Python `InstrumentCashflowEnvelope.to_dataframe()` has the new columns; `accrual_start` and `accrual_end` are `datetime64`.
- `CalibrationConfig.explain` is a wire setting (`{"explain": {"enabled": true}}` in plan settings, Python `CalibrationConfig(explain={"enabled": True})`); it was `#[serde(skip)]` and reachable from Rust only. Bootstrap steps record one `knot_solved` computation step per quote (time, solved value, residual at commit, quote value, evaluations, approximate flag) and global fits record one `global_solve` step (times, solved parameters, iteration and evaluation counts, residual norms). `ExplainOpts` derives `JsonSchema` and deserializes with defaults; a disabled setting is omitted from the wire form.

- Intermediates that were computed and dropped are now result fields; every one is optional on input, so earlier JSON still loads unless noted under "Changed":
  - **Margin.** `ImResult.simm_detail` (`SimmDetail`: per component and bucket, each weighted sensitivity with its risk weight and concentration factor, bucket `k`, per-risk-class margins and the MPOR scale). `XvaResult.cva_rows`, `dva_rows` and `fva_rows` (per time bucket: discount factor, survival and marginal default probability, exposure, contribution; rows sum to the leg). `FrtbSbaResult.scenario_breakdown` (delta, vega and curvature by risk class for every correlation scenario, not only the binding one).
  - **Analytics.** `BetaResult.n_obs` and `confidence_level`; `GreeksResult.n_obs`; `MultiFactorResult.n_obs`.
  - **Statements.** `StatementResult.node_sources` and `get_source` record whether each cell came from an explicit `value`, a `forecast`, a `formula` or a `where_masked` zero; the long table gains a `source` column. `CheckFinding.comparison` and `CheckResult.comparisons` (`CheckComparison`: identity, period, actual, expected, absolute tolerance) cover passing and failing periods. `CashflowBreakdown` gains `opening_balance`, `scheduled_principal`, `mandatory_prepayment`, `sweep_prepayment` and `voluntary_prepayment` (the four sum to `principal_payment`), and `CapitalStructureCashflows.available_cash` is the cash the waterfall allocated.
  - **Statements analytics.** `CorporateValuationResult` gains `wacc`, `periods` (`DcfPeriodRow`: free cash flow, discount years, discount factor, present value), `pv_explicit`, undiscounted `terminal_value`, `terminal_discount_years` and `equity_bridge`. `GoalSeekResult` gains `residual`, `tolerance`, `evaluations` and `converged`. `Explanation` gains `source` and `forecast`, and `ExplanationStep.operation` is set for pure sum/difference formulas.
  - **Attribution.** `PnlAttribution.pv_t0` and `pv_t1` on every method; `waterfall_steps` (`WaterfallStep`: PV before and after each factor, in applied order); `sensitivity_steps` (`SensitivityStep`: sensitivity, observed move and unit, key-rate buckets, explained and second-order P&L) for Taylor and metrics-based attribution.
  - **Portfolio and scenarios.** `PositionValue.fx_rate` and `fx_triangulated`. `ApplicationReport.applied_shocks` (`AppliedShock`: target, magnitude and unit, and before/after level for scalar prices).
  - **Calibration.** `CalibrationReport.solver_method` and `residual_units` as typed fields; `CalibrationDiagnostics.jacobian`; fitted per-expiry vol slice parameters (`FittedSlice`) on the step report.
- Python exposes each of the above as a getter, with DataFrame columns or step tables where the wrapper already had a DataFrame exit.
- Portfolio margin is bound: Python `portfolio.PortfolioMarginAggregator`, `PortfolioMarginResult` and `NettingSetMargin`; WASM `portfolio.PortfolioMarginAggregator`.
- Curve calibration provenance has typed accessors: Python and WASM `DiscountCurve.rate_calibration` / `rateCalibration`, `ForwardCurve.rate_calibration` / `rateCalibration` and `HazardCurve.hazard_calibration` / `hazardCalibration`.

#### Changed (breaking)

- `QuoteQuality.target_value` and `fitted_value` are replaced by `quote_value: Option<f64>`, the market quote in its native units (decimal rate for deposits, FRAs, swaps and inflation swaps; price for rate futures; basis points for CDS par spreads and cross-currency basis; percent for CDS and tranche upfronts). Both solvers wrote `0.0` and the residual into the old fields. `residual` is documented as what it is: the quote instrument's value on the calibrated curve per unit of residual notional, target zero. Python `QuoteQuality.quote_value` replaces the two getters, and the per-quote DataFrames (`CalibrationDiagnostics.to_dataframe`, `CalibrationReport.to_dataframe`, `CalibrationResult.residuals`) have a `quote_value` column in place of `target` and `fitted`.
- `VmResult` gains six required fields that replay the call: `threshold`, `independent_amount`, `collateral_balance`, `unrounded_call`, `mta` and `rounding_increment`. A `VmResult` serialized before this change no longer deserializes.
- `CalibrationDiagnostics.singular_values` and `r_squared` are removed; no producer ever set them.
- `Explanation.breakdown` is empty for a cell whose value came from an explicit value, a forecast or a `where` mask; `source` says which. It used to list the formula's components even when the formula had not produced the number.
- `CashflowRow.native_pv` is required on input, so a cashflow envelope serialized before this change no longer deserializes.
- `TraceEntry::CalibrationIteration` (wire kind `calibration_iteration`) is removed; nothing produced it.
- Rust `BondEngine::price_with_explanation` is removed; it had no production caller. The registry trace above replaces it.

### Attribution API simplification

#### Changed (breaking)

- Rust `attribute_pnl` runs every `AttributionMethod`. `MetricsBased` prices the two endpoints with the default metrics the instrument type supports; it was a validation error. `attribute_pnl_metrics_based` remains the entry point for results that are already priced.
- Rust `AttributionSpec::execute` and `AttributionEnvelope::execute` return a panic inside the pipeline as `Error::Internal`; `execute_contained` is removed from both. Python and WASM behaviour is unchanged.
- Rust long-row projections are imported from `finstack_quant_attribution::long_rows` (`pnl_attribution_long_rows`, `pnl_attribution_wide_row`, `pnl_attribution_carry_rows`, `pnl_attribution_credit_factor_rows`); the crate-root re-exports are removed.

#### Removed

- Rust `ATTRIBUTION_SCHEMA`, `schema::ATTRIBUTION_SCHEMA_BASE`, `AttributionSchema::CURRENT` (use `AttributionSchema::Attribution`) and `Display for AttributionFactor` (it printed the `Debug` name; `as_str` is the wire name).
- The attribution crate's direct `rayon` dependency; its parallel maps go through `finstack_quant_core::parallel`.
