# PR-014 — stored curve views

`curve-chart` accepts generated MarketContextStateWire curve entries. Seven
schema-declared `knot_points` variants use point marks, preserving original state
and tuple references. Compatible overlays use the native categorical legend;
different variants get separate panels. The generated no-knot routes display
base-correlation arrays and parametric model fields without manufacturing samples.

Native axes, annotation marks, publication text, per-variant SVG/PNG handles,
raw native tooltip content and typed focus/activation callbacks are forwarded to
the existing figure wrapper. Optional linking requires caller-owned accepted state
and an explicit point-key mapping. Duplicate overlay IDs fail explicitly. The
component imports the market contract and generated views, not the instrument
catalogue or a WASM runtime.

The retained market fixture contains all nine variants, passes the generated
validator and round-trips through the real Node Market facade. The fixture generator
validates representations; it performs no sampling or pricing. Four focused tests
compare every plotted coordinate to its original tuple, check overlay/facet
membership, reject interpolated geometry and verify both field routes and empty
input. Installed Chromium checks cover raw high-precision hover, custom tooltip
keyboard action, one activation, accepted selection, native annotation and complete
publication export. Light/dark axe checks pass; the screenshot was inspected.

Scoped senior review: PASS after fixing source-label identity, which had reset
tooltip focus during parent renders. No remaining actionable correctness,
performance, abstraction or cleanup findings in this slice. The installed component
uses six registry items, with no instrument catalogue and zero WASM requests.
