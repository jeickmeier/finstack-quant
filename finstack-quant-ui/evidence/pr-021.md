# PR-021 — field validation routing and submission focus

One issue mapper converts canonical validator segments to current editor paths,
including array indices, external tags and map key/value rows. Literal keys such
as `desk.rate[0]/~1` are never interpreted as path syntax or decoded twice.
Ambiguous map rows, unknown fields and unaddressable issues remain in the summary.
The wire codec now supplies structured diagnostic paths for enum/transport and
wide-integer failures; presentation does not parse error prose or duplicate rules.
InstrumentForm delegates to the same SchemaForm implementation.

ErrorSummary includes actual native validation failures, is focusable and retains
structural diagnostics. Invalid submission focuses the first mounted invalid
control, otherwise the summary. The apply action remains available once validation
settles so users can reach errors; invalid values still cannot be submitted.
Both background and submission validation retain edit identity. Editing cancels
acceptance of older successes and failures, including their focus effects.

Focused senior review: PASS. Invalid fixtures cover bond, deposit, FX option,
equity and CDS contracts: decimals, enums, external coupon tags, tuple arrays,
literal map keys, unknown fields and hidden controls. Actual native validation
supplies maturity-before-issue and recovery-limit errors. Old background responses
and old submitted successes/failures cannot replace current state. Codec tests
check literal escaped-key paths and wide-integer bounds without narrowing values.

Validation: ui-check passed 450 tests; the additional old-submit-success regression
passes in the focused 12-case validation run. ui-build and the installed Chromium
form/worker test pass, including real invalid-submit focus, native-error summary
focus, unchanged prior output, zero axe violations and one WASM request. No
full-library or notebook suites ran. This completes Task 2.2.
