# PR-031 — stored FX matrices and full market browser

The browser builds its searchable disclosure tree from the generated market root
and every supplied value, including collateral and hierarchy. Stable record IDs
preserve selection across array reorder; literal map keys and JSON pointers stay
unambiguous. Missing generated roots are explicitly unavailable, distinct from
stored nulls and empty collections. Selected values use the existing exact JSON
copy/print presentation. The navigation viewport is bounded for full desk markets.

Stored curves use the existing node chart or generated no-knot value view. Stored
surfaces can use the existing heatmap with caller-supplied color extents. Raw FX
surfaces use their quote table. Cube state remains explicitly stored JSON until a
host supplies the strike, convention and worker context for an evaluated view via
the object-rendering slot; the browser invents no evaluator inputs.

FX matrices preserve quotes, provider_quotes and pinned_quotes separately, including
all dates and policies. Missing directions and diagonals stay unavailable; undated
entries remain undated. Configuration and the complete original FX state are
available for exact copy. No precedence, reciprocal or triangulated rates are computed.

Scoped senior review: PASS. Five focused tests compare a fresh native calibration
of 12_full_credit_desk_market with its recorded source hash and validate the full
supplemental market natively. They navigate and copy all 769 leaves across both
fixtures, preserve original references, verify selection reorder/removal, literal
map paths, missing fields and all FX sources. Supplements cover every stored curve
variant, dated/policy FX entries, collateral/hierarchy and a nonstandard discount
curve with increasing factors and an explicit negative-forward floor.

The standalone installed consumer navigates every supplemental leaf using search
and user activation, compares displayed values with the canonical source, and
copies the complete FX state. Its existing market form updates the selected curve
only after native validation and submission; a rejected negative factor leaves the
accepted view intact. Invalid submission remains enabled after validation so the
shared form can focus and announce errors; rejection, rather than button state,
is the acceptance contract. The accessibility review caught nested summary/button controls; expansion and
selection now use sibling native buttons. Both themes have zero accessibility violations and
one shared WASM load. No workbench block is imported.

Validation: ui-check (520 tests), installed market-browser consumer build/browser.

full-library/notebook tests or WASM rebuild ran. Task 3.3's standalone portion is
