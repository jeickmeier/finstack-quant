# PR-017 — docs integration and real installed consumers

The docs host now uses Fumadocs' Base UI package at the existing 16.15.5 version,
with registry navigation for primitives, individual components and blocks. The
workbench mounts in the existing docs route and uses the shared installed theme.
Consumer copies are ignored and recreated by the actual pinned shadcn installer;
there is no second hand-maintained component source tree.

The initial real installation failed because shadcn replaced the local WASM
package with its unpublished npm dependency. The local install runner now stages
the same built registry JSON and changes only that dependency to a resolved
absolute file path. It restores the host registry URL and stylesheet after add,
serves the unmodified public registry JSON under `/r`, and disables npm lifecycle
builds so installation cannot overwrite the optimized artifact. This proves the
local HTTP registry/local WASM path; a publicly released npm package is not claimed.

The publication web build now uses release-size, explicit wasm-opt -Oz and the
existing feature allowlist. Its 21,534,873 bytes and SHA-256
`afe247bad5421dce0e95aae10e09d4ee48fbd544205cafe9334e789915ca88bf`
reproduce PR-004. The 25,000,000-byte gate passes. The original 10MB failure remains
in PR-004 evidence. The separate ordinary Node build remains available.

Focused senior review: PASS. Installed imports and worker placement work in both
src-layout docs and root-layout external Next consumers. The external npm package
is copied with --install-links and has the same optimized binary hash. Both actual
production exports pass at root and /finstack-quant: edited-bond results match the
native facade (timestamp excepted), tab state persists, market charts render,
locally served fonts load, and one real worker requests the optimized artifact.
The existing worker corpus also verifies structured pricing/initialization errors,
full-width seeds and their exact export, all request inputs, and asset paths/MIME.
Scoped axe checks report no violations; docs screenshots were inspected.

Validation includes wasm-pkg, ui-check, ui-build, installed docs type-checking,
ui-install-smoke and 51 pricing/returned-object facade regressions. No full-library
suite ran. The full docs build compiles this change but cannot export absent notebook
lab pages in this checkout. Per the user's scope, ui-docs-build exports the real
registry docs route and layout in isolation, with a source-only navigation projection.
Unrelated root/lab navigation prefetches are explicitly excluded and recorded.
This closes the installed registry integration gate; it does not certify the full
analyst-site publication pipeline, notebook output or other library domains.
