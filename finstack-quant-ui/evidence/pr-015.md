# PR-015 — standalone instrument and pricing forms

`instrument-form` uses the generated grouped catalogue and lazily imports the
selected module. Only bond renders in this phase; other discovered types remain
visible as not yet supported. Explicit example loading replaces edits. Validation
uses the shared native validator callback, returns canonical JSON without writing
it into controls, and clears accepted JSON immediately on edits and reset.

`pricing-params-form` reuses date, model and metric primitives. Native model groups
are filtered by the supplied instrument type. The controlled value retains every
supplied field, hidden metric selections, omission versus an empty metric list,
and exact override/history text. Lossless JSON parsing checks syntax only;
financial validation remains native. A caller may supply its own history slot.
Read-only JSON uses the shared viewer.

The installable standalone example has caller-owned state and uses the existing
query/provider/validation hooks; it imports no workbench block. Its retained request
comes from the PR-013 facade fixture. The original production CDS-option market
is now explicitly listed by the generated fixture manifest, alongside the canonical
bond example. The request's curve IDs/dates are the existing PR-009 facade-test
adaptations recorded in `tests/browser/cases.mjs`.

Scoped senior review: PASS after correcting error-path focus and native error
messages, then reproducing and fixing stale asynchronous validation clearing a
new structural error. TanStack Form now owns synchronous structural errors; a
cancellable 250 ms native validation effect owns native status. These states no
longer overwrite each other. A regression resolves old native work after an invalid
edit and asserts the field error and invalid accepted state persist.

Validation: `mise run ui-check` (263 tests), `mise run ui-build`, generated inventory
check, and installed Chromium pricing-form checks pass. Five new focused tests
cover lazy loading, unsupported gating, example replacement, path focus, native
errors, exact optional input transport and the stale validation race. The existing
full-width bond seed tests still run in this scoped suite. The installed browser
compares historical VaR from the complete submitted request with the direct native
facade, preserves original overrides/history, and confirms an unsupported override
containing u64::MAX reaches native validation unchanged and returns its error. That
case proves transport and error handling, not support for that invented override.
Axe reports zero violations; the standalone form screenshot was inspected. Runtime
loading stays lazy for unsupported schemas. No full-library suites ran.

accepted component APIs.
