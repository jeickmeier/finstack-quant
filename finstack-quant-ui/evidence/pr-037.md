# PR-037 — Independent installation matrix

Status: all independent installs and composed production checks passed locally.
All final registry checks passed. Remote CI acceptance remains open.

`ui-install` builds the catalogue and creates one new external Next 16.3.4/React
19.2.8 application per requested item. The pinned shadcn 4.21.0 CLI initializes
Base UI with the `nova` preset, then adds exactly one registry item. No installed
consumer, sibling item or workspace alias is reused. Only declared closure files
are available to the item's TypeScript and production-build checks. The local
registry transport replaces the unpublished WASM dependency with its absolute
local package path; required packages are copied before registry resolution.

Every item receives a statically served browser render/import harness. The visual
harness projects the selected existing gallery example and only its referenced
imports/declarations using the project's TypeScript parser. Fixture data is
supplied by the consumer. Generic schema-form gets a caller-supplied canonical
bond schema rather than an undeclared bond-contract import. Its validation callback
is explicitly a structural-form demonstration, not a native-validation claim.
Actual native validation and pricing are checked by the composed worker suite.

The matrix checks installed target ownership and hashes, production source maps,
page and HTTP failures, displayed errors, and unexpected WASM initialization.
Table-only and chart-only consumers exclude the other runtime; the standalone
selection hook excludes both. The lazy instrument catalogue cannot load schema
payloads eagerly. Reports distinguish subsets from complete runs, and the complete
`ui-install` gate rejects a subset override. Failures preserve their consumer and
log. Concurrent consumers have independent directories, builds and browser contexts;
report writes are serialized.

The standalone chart uses public native selection/cursor controllers with two
charts and ordinary controls. Browser checks cover mirrored accepted marks,
shared tooltips, a pinned action without duplicate activation, explicit clear,
complete editable SVG with embedded fonts, and 1800×1200 PNG output. Six financial
wrappers independently forward publication text, activation, custom tooltip and
shared export props. Surface checks export the primary heatmap, not a separately
titled row/column slice. Vector heatmap rectangles are valid export geometry.

`JsonViewer` gained an optional exact-text download filename; `CashflowViewer`
uses it for `cashflows.json`. The mixed-currency fresh consumer compares displayed,
copied and downloaded bytes against the retained native export. It adds no parser,
currency conversion or typed cashflow reconstruction.

Only after all independent items pass does `ui-install` run the existing production
workbench smoke checks at root and `/finstack-quant`, plus a separate installed
selection route. The real worker checks cover edited bond inputs, options/history,
direct-facade agreement, wide integers, structured failures and asset identity.
The selection route exercises row/cell/chart updates, caller rejection, explicit
clear, nested controls, focus retention and stable semantic identity after reorder.
The faster `ui-install-smoke` task retains its workbench-only default.

The CI `ui-install` job consumes the gallery job's freshly built web/Node WASM
packages, installs locked registry/docs dependencies, then runs the entire gate.
It retains install and composition evidence even on failure. No full-library,
notebook or aggregate-site suites are part of this change.
