# PR-024 — canonical market editor

MarketContextForm reuses the generated market schema and metadata with SchemaForm.
Only curves, stored FX entries and scalar prices are editable. A presentation
callback supplies KnotTable only to the declared curve knot_points field;
base-correlation arrays and parametric model fields retain their schema shapes.
Other market fields, including surfaces, cubes and FX delta surfaces, stay raw and
read-only while remaining in the complete submitted payload. Import accepts
canonical market JSON or a calibration envelope's result.final_market without
rounding JSON tokens; the existing bond fixture can be loaded explicitly.

The shared worker now exposes validateMarket: construct the complete native
Market, export toJson and free in finally. The standalone useMarketValidator hook
retains the existing cancellation and error behavior. No interpolation, rate
calculation or FX conversion is introduced.

Focused senior review: PASS. Read-only data survives editing, failed imports keep
active edits, native domain failures remain visible, successful validation handles
are freed immediately, and complete canonical requests reach existing pricing.

Validation: ui-check, ui-build, six market tests and the freshly installed Chromium
consumer pass. Stored coordinates match the edited tuple exactly; no-knot fields,
stored FX quotes and prices round-trip through native Market. An actual native
calibration result imports successfully. Populated read-only surface/cube/FX-vol
payloads survive export. The browser compares edited-market worker pricing with
the same direct native request, copies canonical JSON, loads one shared WASM asset
and reports zero accessibility violations. An unchanged primitive dropdown test
failed once during the first suite run and passed focused and full reruns.
Task 2.5 remains open for PR-026's workbench integration. No full-library or
notebook suites ran.
