# PR-018 — native table selection and stored-curve linking

The shared table keeps its core-only default feature registration. Linked mode
registers the pinned Table 9.2.4 row and cell selection features, derives controlled
native state from the accepted shared key, resolves functional updaters against
that state and proposes one semantic key or null. Multi-row, sub-row, row/cell range,
cell drag and automatic cell reset are disabled. There is no effect-synchronized
selection copy. Switching feature mode creates a new native table instance.

Rendering IDs remain separate from correspondence keys. Linked columns require
explicit stable IDs. A native active cell requires an explicit row/column address
whose current data maps to the accepted key; many-to-one matches can remain purely
decorative. No native composite IDs are parsed. Missing/reordered rows and unmapped
keys neither retain stale highlights nor clear parent state. Pointer and keyboard
activation use native setters and compose typed notifications once. Nested editors
and actions retain their behavior. External changes do not activate or move focus.
Density, supplied totals and caller-provided empty content extend the shared table;
existing measure and knot consumers retain their core behavior.

The independently installable curve-link example uses the actual stored discount
fixture. Rows select series; cells and chart points select original knots. Explicit
maps tie those targets together. Series outlines use native decorative marks; no
financial curve evaluation, value join, interpolation or aggregate is introduced.
A caller-supplied curve landmark label fixes duplicate accessible names when
multiple independent views appear on one page.

Focused senior review: PASS. Six focused tests cover updater semantics, rejected
proposals, raw bigint values, cell precedence, keyboard activation, embedded editors,
programmatic updates, clear, reorder/removal, independent instances, explicit active
addresses, many-to-one mappings and supplied state/totals. Production Chromium tests
install independent table and linked-example closures, check both directions and
one proposal per gesture, and pass axe with no asset failures. Table-only bundled
modules exclude chart and WASM runtimes; the linked example also excludes WASM.
The two Vite builds run in separate processes because Tailwind's imported-CSS cache
otherwise reuses font URLs across builds. Screenshot inspected.
