# PR-011 — typed chart interactions and linked selection

The React-only `use-linked-selection` hook owns accepted string/null identity in
controlled or local mode. Equal accepted proposals are suppressed. The chart
adapter derives native `keyedSelection` from `controlledSignal` every render;
there is no effect synchronization, global bus, cursor-to-selection write, or
parsing of native point keys. `whenSelected` paints every matching datum without
adding interaction targets. Missing data does not silently clear the parent's key.

The wrapper forwards native typed focus, group, activation and tooltip-body
callbacks. Original datum and coordinate types remain inferred. Activation is a
notification after the native controller proposes selection, never a second
accepted-state writer. Custom bodies can compose native default rows and pinned
controls; Escape remains native dismissal.

Scoped review found and fixed two integration defects. Renderer identity used to
change on every parent update, which cleared keyboard focus. The renderer now
depends only on prose and presentation; unchanged font-load notifications do not
replace it, including those emitted while embedding fonts for an export. Native
0.18.0 container keyboard handling also consumes Enter from custom tooltip
controls. The body boundary stops non-Escape propagation without preventing the
control's browser default, preserving native pinning, placement and dismissal.

The installable `LinkedFigureExample` demonstrates two compatible charts sharing
one parent-owned native cursor, controlled acceptance/rejection, ordinary controls,
reorder/removal, a pinned keyboard detail action, and separate focus/activation
notifications. A second parent in the browser fixture proves state isolation.

Validation: `mise run ui-check`, `mise run ui-build`, `test:interactions:browser`
and the publication `test:figures:browser` regression harness. Selection tests cover
local equality/clear, controlled acceptance/rejection/programmatic values, original
datum identity, reorder/removal and many-to-one decorative matches without extra
hit targets. The browser checks native focus and selection callbacks, keyboard
pin/action/dismissal, export while the action is focused, independent parent cursors,
and blank-pointer null clearing. The build module inventory excludes table/WASM
runtimes; the browser records no WASM requests. No full-library suites ran.

The component gate initially had one timing-sensitive existing money-select test
failure during concurrent browser work; its isolated rerun passed. The final gate
runs after the interaction fixture. Table adapters remain exclusively PR-018;
canonical curve forwarding remains PR-014.

Native API evidence comes from the installed pinned 0.18.0 declarations and
[focus/interaction documentation](https://github.com/TanStack/charts/blob/v0.18.0/docs/reference/focus-and-interaction.md).
