# PR-032 — generated calibration form and native worker workflow

CalibrationForm renders the generated calibration root, including the published
MarketQuote, step, prior-market and solver-setting shapes, through SchemaForm.
It requires an explicit initial envelope and native validation callback. Submission
returns only the canonical native envelope; unsupported initial roots and malformed
JSON show errors instead of falling back to a fixture. Structural errors reuse the
existing precise control paths; native semantic errors without a reliable field
path remain in the summary. No financial defaults or schema copies are introduced.

The shared worker adds validateCalibration, dryRun and calibrate as direct calls
to the published calibration facade. The existing cloneable error envelope retains
kind, stage, step_id, solver_diagnostics, details and cause, including absent fields.
useCalibrate and useCalibrationDryRun retain the entire immutable JSON envelope,
operation and worker session in query identity. Null disables work; explicit
submission controls solving. useCalibrationValidator ignores superseded results.

Scoped senior review: PASS. Fourteen real Node/Comlink tests discover all 12 Phase 0
calibration inputs and compare complete canonical validation, dry-run JSON and solve
results against direct native calls, with no skipped fixtures or normalized-away
result fields. Failure cases cover malformed ingestion, missing quote sets,
unacceptable SABR targets and a solver failure with diagnostics. The complete
failure payload matches native output. Query tests exercise changed quotes,
settings, supplied prior curves, changed prior knots, cache hits and session changes.
The returned final_market is used in a complete native pricing request.

Seven form tests edit quote rate, prior-market knots and a diagnostics setting,
compare the exact accepted canonical envelope, retain semantic errors in the
summary, and reject invalid initial roots. The installed standalone browser checks
initial and edited solves, dry-run errors, target/solver failures, unavailable
solver diagnostics, exact result/error data, market browsing and the explicit
returned-market-to-pricing action. Both themes have zero axe violations, no page
errors, one shared worker WASM load and no main-thread WASM import. Its screenshots
were visually inspected.

Validation: ui-check (541 tests), focused real-worker/form/query checks, installed
consumer build and Chromium checks. No full-library/notebook suite or WASM rebuild
ran. This completes Task 3.4's request/editing portion; PR-033 owns report views and
PR-035 owns workbench integration.
