## Build and artifact identity

The plan's original `wasm-pack ... --profile release-size` command compiled Rust
but failed in its implicit `wasm-opt -O` step: the custom profile did not receive
the existing release optimizer's feature allowlist. No source or feature changes
were made. The reproducible build instead separates compilation and optimization:

```sh
wasm-pack build finstack-quant-wasm --target web --profile release-size \
  --no-opt --out-dir /tmp/component-registry-pkg-size
cp -R /tmp/component-registry-pkg-size /tmp/component-registry-pkg-size-oz
wasm-opt -Oz --enable-bulk-memory --enable-nontrapping-float-to-int \
  --enable-sign-ext --enable-mutable-globals --enable-simd \
  /tmp/component-registry-pkg-size/finstack_quant_wasm_bg.wasm \
  -o /tmp/component-registry-pkg-size-oz/finstack_quant_wasm_bg.wasm
node finstack-quant-ui/tests/browser/size.mjs \
  /tmp/component-registry-pkg-size/finstack_quant_wasm_bg.wasm \
  /tmp/component-registry-pkg-size-oz/finstack_quant_wasm_bg.wasm \
  /tmp/pr004-size.json
```

Use fresh output directories. The size command writes its report and exits 1 for
an exceeded limit. Its optimizer flags match the unchanged release allowlist in
`finstack-quant-wasm/Cargo.toml`. Toolchain: rustc 1.91.1, wasm-pack 0.14.0,
wasm-opt 130. Default features and canonical Rust/binding/schema sources remain
unchanged. The optimized artifact SHA-256 is
`afe247bad5421dce0e95aae10e09d4ee48fbd544205cafe9334e789915ca88bf`.

The harness copies the unchanged public facade into its temporary package and
pairs it with the optimized binary's own wasm-bindgen glue. Both root and
`/finstack-quant` exports pass the actual pricing, bigint, error, cashflow and
initialization corpus. The requested emitted WASM file's SHA-256 and its HTTP
content length are checked against the selected artifact. Chromium evicts large
worker response bodies from its inspector cache, so identity is checked against
the file served unchanged by the local static server, without a second fetch.

## Browser method and scope

```sh
PLAYWRIGHT_BROWSERS_PATH=/tmp/component-registry-browsers \
REGISTRY_WASM_PACKAGE=/tmp/component-registry-pkg-size-oz \
REGISTRY_SMOKE_DIR=/tmp/pr004-browser \
npm --prefix finstack-quant-ui run test:footprint
```

The final measurement ran after component checks, in a fresh browser process with
no previous navigation. Initialization measures the Comlink initialize round trip
following Worker construction, including remaining worker loading and WASM
fetch/compile/init. It is a single local-server observation. Each instrument's
first loader sample includes network, evaluation and cached validator construction;
a separate warm reconstruction sample excludes network. One valid example and
20 rounds each of invalid-tag and missing-object validation exercise every type.
The source fixture manifest determines the required types; none are omitted.

ESM modules and their validators stay cached. CDP garbage collection runs after
each type, followed by `Runtime.getHeapUsage`. These numbers describe retained
main-realm V8 heap, not total browser RSS or the worker's WASM memory. Resource
Timing records each newly loaded response; the server does not compress JS, so
encoded and decoded sizes match. The recorded per-type response bodies total
37,565,604 bytes, including shared dependencies when first fetched. The observations
complete the prescribed corpus; they do not prove an unstated memory budget.

Scoped review checked exact artifact selection, matching generated glue, lazy
loading, complete fixture coverage, validation behavior, timing boundaries, heap
collection, error reporting, size exit-code behavior and temporary-file cleanup.
`ui-check` passes 138 tests, formatting, TypeScript and generated drift. Fresh web
and Node WASM builds were completed in PR-003 immediately before this slice.
Full library test/review suites, full `gen-check`, `rust-check-schemas`, and the
aggregate unchanged-binding lint/doc/test suites were not rerun under the user's
component-only instruction. These validation boundaries remain unchanged; the
revised browser feasibility gate permits PR-005 to begin.

## Acceptance revision

The original 10 MB result remains recorded in `gateRevision` in the JSON evidence
and the preceding commit. The revised gate is 25 MB optimized raw, with gzip and
Brotli reported separately. The complete 78-instrument corpus must still finish
without disabling validation or dropping instruments. Retained V8 heap remains
visible (656,945,132 bytes on this device); completion is not a memory-budget or
small-device performance guarantee. No Rust or binding changes are needed for
this acceptance revision.
