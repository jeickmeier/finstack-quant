# PR-006 — shared theme and fonts

`tokens.json` owns UI/semantic colours, six fixed series colours, heatmap colours,
typography, geometry, density and font package/face selections. One generator
emits CSS and shadcn `cssVars`; both outputs are tracked for generation drift.
The default primary is deep teal, with warm light surfaces and dark equivalents.

IBM Plex Sans 400/400 italic/500/600 and IBM Plex Mono 400/500 come from Fontsource
5.3.0 packages under SIL OFL-1.1. The registry ships CSS imports, not font binaries.
A single tenant stylesheet overrides the same properties in both modes. Densities
use 28/30 px row/field heights (compact) and 36/36 px (comfortable).

Scoped review: PASS. Confirmed independent density/theme selectors, tenant font
variable behavior, identical light/dark keys, deterministic outputs, direct
parser dependencies, opaque colour checks and specified contrast. The literal
checker rejects CSS/TS colours, named colour shorthands, palette utility classes
and literal font families outside the theme. It preserves computed geometry.

Validation: `mise run ui-gen`, `mise run ui-check` (163 tests), `mise run ui-build`,
and `test:theme:browser`. The production Vite consumer extracts the built theme
item, applies Tailwind, then serves static files. Chromium loaded all six faces
with successful font requests; all four theme/density combinations and both
tenant modes passed. See [browser measurements](pr-006.json). Screenshot inspected
locally at `/tmp/pr006-theme.png`. No browser dev server or full library suite ran.

The scoped regeneration also exposed PR-005's stale manifest-test expectation;
that assertion was corrected and committed to PR-005 before this slice. The new
theme outputs are now included in the generated-artifact inventory as well.
