# PR-003 — production static-export worker feasibility

Spec §9 static-export verdict: **pass for the component-registry scope**.
The browser-size and validator-memory gate remains PR-004.

Next 16.3.4 / Turbopack production exports passed in Chromium 145.0.7632.6 at
`/` and `/finstack-quant`. The docs configuration sets Turbopack's root to the
repository for local package resolution and reads `NEXT_PUBLIC_BASE_PATH`.
No custom WASM loader, development server, Rust feature changes, or main-thread
financial computation was used. See [machine-readable evidence](pr-003.json).

Checks exercised actual facade calls through a Comlink module worker:

- Bond and stochastic pricing match direct facade results, with each call's
  wall-clock timestamp checked separately through Rust-validated round-trip export.
- The actual derived seed `10049819788103739979` remains bigint above 2^53 and
  exports as an exact numeric token.
- Bad instrument and missing-market errors retain the actual facade fields.
- Original bond cashflow JSON text survives unchanged.
- Worker scripts return JavaScript MIME types; WASM returns `application/wasm`.
  All successful asset paths respect the configured base path.
- Successful initialization reports a worker environment. A deliberately missing
  WASM URL reports failed initialization; its expected 404 appears in the evidence.
- Main-thread WASM instantiation is disabled by the browser test and never occurs.

The full docs **frontend export** was built for both paths with a temporary probe
route. Its existing curriculum metadata was copied from the main checkout, and a
labelled non-financial lab fixture supplied an otherwise empty generated collection.
Notebook results, publication freshness, Python and full-library suites were not
revalidated. This is not a docs publication/release certification. The temporary
route and lab document were removed after extraction of the isolated harness.

The retained harness creates a temporary Next app under `docs-site`, imports the
same exported Next configuration and resolves the same pinned packages, builds
production exports for both paths, serves only static files, and removes its app
in `finally`. Both isolated exports also passed independently.

Commands:

```sh
UV_CACHE_DIR=/tmp/component-registry-uv-cache UV_NO_SYNC=1 mise run wasm-pkg
mise run ui-check
npm --prefix docs-site run build
NEXT_PUBLIC_BASE_PATH=/finstack-quant npm --prefix docs-site run build
npm --prefix finstack-quant-ui exec -- playwright install chromium
npm --prefix finstack-quant-ui run test:browser
```

The browser run used `PLAYWRIGHT_BROWSERS_PATH=/tmp/component-registry-browsers`.
`REGISTRY_SMOKE_DIR` selects the report directory; the default is a fresh temporary
directory. `REGISTRY_EXPORT_DIR` lets `tests/browser/smoke.mjs` inspect an existing
export, including the real docs output. Scoped review checked package ownership,
static asset paths, exact host transport, explicit errors, cleanup and absence of
financial logic. Full `gen-check` and library review suites were not run.
