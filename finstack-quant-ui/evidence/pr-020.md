# PR-020 — edited pricing matrix

The checked pricing-case manifest has exactly one positive case for each of the
78 generated instrument tags. Each case pins its canonical instrument fixture and
market source by SHA-256, records explicit setup patches, the complete request
(including null optional inputs), an actual financial control edit, and baseline
and edited native-value regression anchors. The shared market is an input-only
test scenario with literal quotes and documented canonical source shapes; four
cases reuse production fixture markets. Captured values are routing regression
anchors, not independent economic benchmarks.

Every case renders the complete SchemaForm, edits the recorded input, validates
through the production Comlink service in a real Node worker, submits canonical
JSON, and prices the edited request through that worker. Results match the direct
published web WASM facade exactly except native clock timestamps, including nested
composite result timestamps. Currency, decimal strings, bigint fields, measures,
details, errors and all other metadata remain part of comparison. The value must
change from baseline and agree with the case's recorded native anchor. Exported
results also pass native canonical validation. No skips, family exemptions or
JavaScript pricing substitutes are used.

The bond case exercises nonempty requested metrics, theta options and historical
market scenarios. Stochastic cases pin their seed scenario and use 64 paths for
routing coverage, without claiming convergence. Hull–White cases supply explicit
parameters. Bond futures embed the source CTD bond; commodity forwards explicitly
set an entry price; FX monitoring dates and inflation-index setup satisfy native
requirements. Three unsupported instrument/model combinations compare full native
errors. Source or inventory drift fails the matrix.

Focused senior review: PASS. The pricing controls exposed a DecimalInput defect:
its field path was sent to the input instead of FieldFrame. Passing it to
FieldFrame restores addressability for decimal controls and summary focus. The
worker harness is shared with existing lifecycle/error tests; it cleans up native
worker processes and temporary builds on success or failure.

Validation: ui-check (438 tests, including both 78-instrument matrices), ui-build,
and 51 scoped facade regression tests. No full-library or notebook suites ran.
Together with PR-019, this closes Task 2.1's renderer and edited-pricing routing
criteria. Financial-model certification and later release gates remain separate.
