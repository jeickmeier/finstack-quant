# PR-038 — Print and publication verification

## Scope and review

The existing workbench captures its last completed request/result for printing,
shares the existing cashflow query, waits for data and fonts, and restores its
input tabs/disclosures after the browser dialog. Its existing instrument JSON,
market browser, measures, valuation details and raw-cashflow viewer provide the
report. Shared print styles handle A4/Letter, light tokens, wrapping raw text,
static repeating table headers and complete figures. No financial calculations,
typed cashflow rows or second figure/PDF renderer were introduced.

Focused senior review: PASS after correcting sticky print headers, fixed-height
chart whitespace, table-caption breaks and snapshot ownership for custom market
views. No unresolved source findings, speculative abstraction or extra runtime
dependency. Printing native cashflow failures retains their error; it does not
invalidate the successful valuation. Scenario controls are excluded from print.

## Automated evidence

- `mise run ui-publish-check`: fresh one-item CLI installation, TypeScript and
  Next production build; bond and mixed-currency reports at A4 and Letter;
  original instrument/market request identity; direct native cashflow equality
  and exact downloaded bytes; completed-state restoration; offline SVG fonts,
  text bounds and PNG dimensions. Four PDF text/font/vector/bounds checks pass.
- PDF checks isolate Mono Regular JSON from rotated figure labels and footer
  page numbers, then ignore print-added whitespace only. This preserves every
  JSON token, amount, currency label and native field. No report page contains
  a raster image; the chart paths and body text remain vectors/text.
- `pr-038-publishing.json` retains PDF hashes, page sizes/counts, exact-text
  comparisons, fonts, vector counts, offline bounds and production checks.
- A 900 × 600 SVG and 1800 × 1200 PNG share the complete title/subtitle, axes,
  legend, native annotations, caption and sources. The app was dark; exports
  explicitly used the light theme. SVG embeds licensed Fontsource fonts and
  reopens with network disabled. The PNG corresponds to 300 PPI at 6 × 4 inches;
  no native DPI-metadata claim is made.
- Focused workbench tests: 16 passed, including a delayed cashflow response
  proving no premature print and one query shared by preparation and viewer.
- `mise run ui-check`: generation, formatting, tokens/contrast, dependency
  ownership and TypeScript passed; **556 tests / 42 files passed** in 68.98 seconds.
  The existing jsdom canvas notice does not affect the real-browser figure checks.

## Desktop inspection

On macOS, Pages 14.5 imported the actual exported SVG into a fresh blank layout.
The figure was placed at exactly 432 × 288 points (15.24 × 10.16 cm / 6 × 4 inches).
IBM Plex Sans and Mono 400/500/600 from pinned Fontsource 5.3.0 were converted from
WOFF2 with fontTools 4.65.0 and registered in CoreText session scope for the check;
all six faces registered successfully and were unregistered afterward. No fonts
were installed permanently. The document is retained locally in the QA output
folder, and [the placement screenshot](pr-038-pages.png) records its dimensions.

Title, subtitle, axes, tick labels, legend, callout, figure note, caption and
sources remain visible with matching light styling and no clipping. Pages' SVG
placement passes. Its optional **Break Apart** conversion warns about unsupported
parts and discards SVG text/axes: that conversion is explicitly unsupported in
the usage docs. It was undone and the intact SVG saved. Editable text and vectors
remain in the original SVG; no editable-Pages-shape parity is claimed.
