# PR-009 — native worker and complete queries

The registry now ships one shared browser worker per FinstackProvider. It calls
the published facade for pricing, validation, cashflows, model/metric/calendar
registries and canonical result export. All seven price inputs are forwarded.
Absent models map to `default`, exactly as the facade's `pricing.rs` does. Market
handles are keyed by full original JSON content in a four-entry LRU and freed on
eviction/disposal. No market reconstruction or financial calculation is added.

Every operation uses an explicit envelope. Native error fields and nested Error
causes survive transfer; Query receives a reconstructed FinstackError. Structured
clone retains bigint results. Cashflows remain the original native string.
Closing a browser client rejects in-flight requests and terminates the worker,
releasing its WASM instance and handles. Reset creates a fresh worker/session.

Pricing keys snapshot all inputs, including options and history, without parsing
JSON or equating empty selections with omissions. Immutable queries use infinite
staleness within the worker session. Validation debounces 250ms and withholds
results/errors immediately when either text or form revision changes. Real
native registries supply option hooks; there is no local domain option table.

Scoped review: PASS. Reviewed input forwarding, handle ownership, initialization
and crash paths, SSR, unmount/reset, complete query identity and stale validation.
Tests caught test-harness output naming/dependency-resolution issues and the docs
site's TypeScript 7 configuration requirements. Exported build output is excluded
from subsequent source checks. No compatibility fallback was added.

Validation:

  final `uv run` attempted an unrelated Python dependency rebuild; it was stopped
  and the task completed with synchronization disabled.
- `mise run ui-check`: 233 tests, including five real Node-worker tests and five
  React/transport lifecycle tests, generated drift, formatting, tokens, registry

- `mise run ui-build`: installable registry JSON.
- Retained Next production static-export browser harness, now using the actual

The Node-worker tests use pkg-node, compare every independently changed pricing
input with the direct facade, demonstrate query reuse only for equal requests,
exercise successful historical VaR and its missing-history failure, count native
market construction/freeing, and check revision tags and native option lists.
Initialization metadata/cause preservation additionally uses a controlled failing
initializer; the browser test supplies the actual asset-failure evidence.

These transport tests use the ordinary release package. PR-004's optimized raw
size gate remains specific to the release-size artifact; ordinary release bytes
are not claimed to satisfy that limit. No full library test/review suites ran.
