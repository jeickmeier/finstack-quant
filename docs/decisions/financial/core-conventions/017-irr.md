# CORE-CONVENTIONS-017: Unique-return IRR/XIRR with log-growth Brent solving

- Decision status: **Draft — observed implementation, adoption pending**.
- Implementation status: **Observed**, scoped to `cashflow/xirr.rs`.
- Validation status: **Evidence inspected/located, not executed**. The linked tests establish available evidence, not a passing result or methodology approval.
- Audit date: **2026-11-05**. Source revision: `7e82fd03ad98346727769e88dd5ac5d84b56e9fc`; see [scope and inventory](README.md).

## Choice, scope and rationale

Solve `sum(C_i/(1+r)^t_i)=0` only for streams with exactly one nonzero sign change after applicable netting. The source explicitly rejects ambiguous/nonconventional streams rather than selecting a root by guess. Periodic IRR returns a rate per input period; XIRR annualizes using an explicit day count. The supported domain is a finite representable `f64` rate greater than -1.

## Algorithm

1. Periodic times are original integer indices, preserving gaps created by zero amounts. XIRR validates finite amounts, sorts dates and uses Neumaier summation to identify nonzero net dates; fully cancelled dates are removed before selecting the first date as time origin. It retains original components of surviving dates for subsequent compensated aggregation.
2. XIRR computes signed year fractions from that first date using **default** `DayCountContext`, sorts by resulting time, and nets all equal year fractions with compensated summation. Synthetic day counts can map distinct dates to the same time. Remove zero nets.
3. Shared solver rejects nonfinite times/amounts and fewer than two nonzero points, shifts times by first remaining time, and requires exactly one sign change. Zero-sign values are ignored. More than one sign change errors even if a particular polynomial happens to have only one real admissible root.
4. Use `x=ln(1+r)`. Store log absolute amount and sign. Evaluate each log-PV `a_i=ln|C_i|-t_i*x`, subtract max(a), then sum signed exponentials and gross absolute exponentials separately with Neumaier compensation. Return signed PV/gross PV as the relative objective; nonfinite max yields infinity.
5. Initial guess defaults 0.1 and must be finite >-1. Evaluate its log-growth objective; exact zero returns the guess. Otherwise its sign relative to first flow chooses which side of the full log-domain bracket to replace. Lower rate is `-1+EPSILON/2`, upper log-growth is `ln(f64::MAX)`. Equal nonzero endpoint signs error as unrepresentable root.
6. Brent solve in the bracket uses absolute log tolerance `1e-12` and maximum 100 iterations. Convert with `exp_m1`; require finite rate >-1 and recomputed relative residual <=`1e-8`, otherwise error. No Newton or arbitrary scan fallback is used here.

## Selection, conventions and controls

Caller supplies flows, optional guess and XIRR day count; solver tolerances/domain are internal constants. The guess narrows a unique-root bracket and never chooses an economic root among alternatives. Negative and very large positive returns are supported only when representable with the residual accuracy. Cashflow signs represent payments/receipts from one perspective; no currency or calendar is carried by raw f64 amounts.

## Limitations and failure

XIRR cannot supply a calendar/frequency/coupon period: Bus252, ACT365L and ACTACT ICMA fail on nonempty intervals requiring that context. `OneOne` collapses all nonorigin dates to one unit, and 30/360 can collapse distinct dates; aggregation is intentional. Exactly one sign change gives at most one admissible root but not representability within f64. It does not establish the economic comparability of mixed units/currencies or an Excel-compatible multiple-root policy.

## Alternatives and tradeoffs

Periodic versus dated timing is supported; nonconventional multi-root search, MIRR, caller-tunable precision or context-aware XIRR are unimplemented alternatives. Log scaling avoids raw notional overflow and makes the residual scale-free; a residual bound is not the same as a fixed error bound on r for poorly conditioned streams.
