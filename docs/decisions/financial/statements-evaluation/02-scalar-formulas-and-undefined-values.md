# STATEMENTS-EVALUATION-002 — Scalar formulas, boolean control flow and undefined values

Decision status: **Accepted for the full scalar formulas and unavailable-value contract (2026-11-15)**. Implementation status: **Reconciled (2026-11-17; rounding mode settled by owner resolution 2026-11-18)**: formulas evaluate to typed values (`evaluator::value`): a finite scalar, exact `Money`, a Boolean or an unavailable value with its reason. Arithmetic is checked, with an undefined domain, division or remainder by zero, overflow and mixed units as errors naming the node and period; same-currency money adds, subtracts, compares, sums and averages as exact decimals; comparisons use the represented values with no tolerance; `if`, `and`, `or` and `not` require Boolean operands at model build and at evaluation and evaluate lazily, and `and` and `or` use strong three-valued logic (a false operand decides `and`, a true operand decides `or`) and an unavailable `if` condition makes the result unavailable; `is_missing` is true only for an unavailable value and `coalesce` returns the first available value including zero; `sum`, `mean`, `min` and `max` need every operand; scalar `round` defaults to zero places with ties away from zero and monetary `round` needs an explicit scale; `clamp` includes both endpoints and rejects reversed bounds; `annualize` needs a positive finite factor and `annualize_rate` an explicit method (`0` simple, `1` compound) with the compound domain from −100%. Monetary `round` applies the function's ties-away-from-zero mode and `floor`, `ceil` and one-argument `round` reject money at build; stating the rounding mode in the formula remains open in the [follow-up register](../FOLLOW_UPS.md). Integer arguments of `round` and `shift` are exact. Validation status: **Qualified** by a truth table over available, unavailable and error operands for each control, `coalesce` returning an available zero, `1/0`, `ln(-5)` and overflow as errors, and compound annualization at −100% and below. ## Accepted decision for scalar formulas and unavailable values

1. Use checked scalar arithmetic. Compare scalars at their represented values and same-currency money as exact decimals. Apply tolerance only when explicitly selected. Invalid domains, division or remainder by zero, and overflow produce errors. [Formula units and currency](../statements-contracts/05-currency-dimensions.md#accepted-decision-for-formula-units-and-currency).
2. Require Boolean controls and evaluate `if`, `and` and `or` lazily. A required condition that is unavailable yields an unavailable result. `is_missing` is true only for absence or a documented unavailable state. `coalesce` returns the first available value, including zero, or an unavailable result if no argument is available. It propagates errors from evaluated arguments. [Formula-check evaluation](../statements-contracts/15-formula-checks.md#accepted-decision-for-formula-checks-and-coverage).
3. Require all operands of `sum`, `mean`, `min` and `max` to be available and propagate an unavailable operand. Use checked scalar accumulation and exact monetary arithmetic for the corresponding operations. [Monetary arithmetic](../core-conventions/012-money-decimal-precision.md#accepted-decision-monetary-precision-rounding-and-currency-identity).
4. Scalar rounding takes an exact integer precision, defaults to zero decimal places and rounds midpoint ties away from zero. Monetary rounding requires an explicit scale and uses the one stated mode, midpoint ties away from zero (owner resolution, 2026-11-18: the formula language has no mode argument). Clamp uses compatible, ordered bounds and includes both endpoints. [Monetary rounding](../core-conventions/012-money-decimal-precision.md#accepted-decision-monetary-precision-rounding-and-currency-identity).
5. Require an explicit positive finite annualization factor. Annualize flows by multiplication. Annualize decimal rates using an explicit simple or compound method. Simple annualization uses `rate × factor`, and compound annualization uses `(1 + rate)^factor − 1`. The compound domain includes −100% and rejects rates below it.

## Audited input domain and conventions

The sections below describe the implementation audited on 2026-11-05, before reconciliation.

The DSL evaluates floating-point expressions with operation-specific undefined handling. Arithmetic values preserve the declared node units established by semantic analysis; decimal rates remain decimal, and no implicit sign or currency conversion occurs in these kernels. The implementation rationale is direct compositional expression evaluation. Adoption is pending for individual numerical tolerances and missing-data operations, subject to accepted [ADR 0009](../conventions/0009-missing-and-invalid-data.md).

## Audited algorithm and controls

- Addition, subtraction, multiplication, negation, absolute value, floor/ceiling, power, logarithms, exponential and square root use ordinary `f64` behavior. Division/remainder by exact zero return NaN and a division diagnostic when a node identity is available. Other domain failures may propagate NaN/infinity until the result layer records them.
- Equality uses `abs(a-b) <= 1e-10`; inequality uses `> 1e-10`. This is an absolute tolerance, independent of units or value scale. Both comparisons are false for a NaN difference. Ordered comparisons use normal IEEE comparisons. `sign` preserves NaN and maps infinities to their sign.
- Boolean truth means finite and nonzero. AND/OR and `if` evaluate only the required branch; boolean consumers retain a nonfinite-operand flag for masking diagnostics. `not(nonfinite)` returns true under this truth rule. `is_missing` tests nonfiniteness, not merely absence of a map key.
- `coalesce` lazily returns the first finite evaluated argument, but does not catch an evaluation error. N-ary `sum`/`mean` evaluate all arguments, discard nonfinite values with a skip warning and use compensated summation; no finite arguments gives NaN. N-ary `min`/`max` fold left to right using the shared comparison semantics: NaN behavior can depend on argument order and right-hand ties win.
- `round(value, digits=0)` requires a finite integer precision fitting `i32`, using the integer tolerance before conversion, and delegates to half-away-from-zero rounding. `clamp` returns NaN for any NaN operand or reversed bounds; otherwise it applies `min(value,hi).max(lo)`, including ordinary clamping of infinities.
- `annualize(value, periods_per_year=current_frequency)` multiplies by the frequency; a nonpositive frequency errors, while the local check does not categorically reject positive infinity. `annualize_rate` requires rate, frequency and a numeric compounding flag: any NaN argument first produces NaN, a nonpositive frequency errors, flag zero gives `r*p`, and any other non-NaN flag gives `(1+r)^p-1`. A nonfinite compounded result becomes NaN with tracing diagnostics. The flag is not restricted to finite Boolean values.

## Selection, failures and alternatives

Function dispatch is an explicit match over the parsed function enum. Standard handlers enforce their arity; cumulative and full-history statistics have the separate surplus-argument discrepancy in [record 04](04-historical-statistics-and-ewm.md). Formula evaluation errors propagate with active-node context; `coalesce` is not an error-recovery operator. Finite-only sums and ordinary arithmetic intentionally differ, so a blanket claim that all missing inputs fail or all missing inputs are skipped would be inaccurate.

The audited equality tolerance is absolute and can affect scaled amounts and small rates. The current flow annualization handler requires an explicit factor. The rate handler still selects compounding through a numeric flag. [Current dispatch](../../../../finstack-quant/statements/src/evaluator/formula_dispatch.rs).
