# Features algorithm methodology inventory

**Scope:** all **11 Rust source files** in `finstack-quant/features/src`, audited at `7e82fd03ad98346727769e88dd5ac5d84b56e9fc` on 2026-11-05: **8 algorithm-bearing files and 3 support files**, no dedicated test-only or generated Rust source files. [coverage.json](coverage.json) maps every assigned source exactly once with its supplied, verified SHA-256 digest. There are **22 detailed Draft records** and **59 algorithm-level inventory rows**.

Every assigned runtime file was read in full, including dispatch/defaults, missing/domain rules, private numerical helpers, public/serde construction boundaries and code following test modules. Both feature integration-test modules and selected core dependencies, schemas and binding callers were inspected for the stated evidence roles. Production algorithms were not executed: **no runtime edits, builds, tests, benchmarks or numerical experiments** were performed. Static hash/link/table checks validate documentation coverage only.

The scope is generic numeric panel features; it has no instrument, Money, currency, Date, calendar, frequency or price-adjustment model. Caller-supplied keys define the population and ordering. Records cover every time-series/cross-sectional/pairwise selector, grouped execution, neutralization, weight compositions and typed/JSON pipeline. Core owns delegated compensated sums, sample covariance/variance and inverse-normal calculations; nalgebra owns the SVD decomposition. This inventory records how features selects and interprets them, not a new audit of their entire crates or bindings.

[ADR 0009](../conventions/0009-missing-and-invalid-data.md) preserves distinctions among invalid, missing and unestimable data, while its concrete performance-panel rules remain scoped to analytics. [Reproducibility invariants](../../../../INVARIANTS.md#21-reproducibility-tiers) limit cross-target claims. No Draft feature method is adopted by documenting it or locating tests.
