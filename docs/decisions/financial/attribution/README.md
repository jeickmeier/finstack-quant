# Attribution algorithm methodologies

- Scope: all **29 Rust source files** in `finstack-quant/attribution/src`, including the schema binary, feature-gated schema module and dedicated source test module.
- Audit date: **2026-11-05**. Source revision: `7e82fd03ad98346727769e88dd5ac5d84b56e9fc`.
- **16 detailed Draft methodology records**; observed implementation is distinct from pending adoption. Source hashes and exact classifications are in [coverage.json](coverage.json).
- Classification: **24 algorithm, 4 support, 1 test**. Every assigned runtime implementation was inspected; trailing inline test modules were located structurally so no later runtime section was excluded. Selected tests were inspected and others located. Tests/builds and numerical fixture regeneration were **not run**.

The runtime audit covers dispatch/defaults, economic factor restoration, ordered/independent revaluation, finite differences and move pairing, carry/cash, credit hierarchy, amount transformations, return contributions and reporting contracts. The table splits important variants within the detailed records. Accounting reconciliation alone does not prove economic accuracy; no method is described as adopted merely because it is implemented.

## Boundaries and evidence

Instrument pricing, period cash classification, market measurement and recalibration kernels are delegated to the existing valuations/core/calibration layers; factor model estimation belongs to the factor crate. Their callers and parameter/units contracts were traced here, without claiming this catalogue owns those source files. Market/config schema examples are support code, not pricing fixtures. No runtime source, tests, fixtures or accepted policy was changed.

[QuantLib attribution parity tests](../../../../finstack-quant/attribution/tests/attribution/quantlib_parity.rs) consume stored bond, IRS and FX-forward fixtures; the sampled [bond fixture](../../../../finstack-quant/valuations/tests/data/quantlib_parity/bond_5pct_10y_usd.json) identifies QuantLib 1.43 and explicit curve/settlement conventions. These are existing external-reference expectations, distinct from [analytical self-consistency](../../../../finstack-quant/attribution/tests/attribution/analytical_self_consistency.rs) and the many synthetic/invariant/roundtrip tests. They were not executed or regenerated here, and they do not qualify every method, product, factor combination or fallback. Reference provenance and applicable accuracy tolerances remain record-specific adoption requirements.

Adjacent catalogues: [portfolio attribution](../portfolio-attribution/README.md) owns portfolio endpoint/position adapters; [scenarios](../scenarios/README.md) owns scenario roll and horizon orchestration. This catalogue documents the shared attribution kernels they call. Findings and unresolved policy/evidence qualifications are tracked in the [attribution follow-ups](../FOLLOW_UPS.md#attribution); [central follow-ups](../../FOLLOW_UPS.md#financial-methodology-audit) coordinate cross-scope work.
