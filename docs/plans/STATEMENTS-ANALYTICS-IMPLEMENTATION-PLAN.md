# Statements Analytics implementation plan

This plan covers the 16 Valuation and 18 Credit decisions accepted on 2026-11-15. The accepted sections define the implementation and the follow-up register defines the outstanding reconciliation and independent qualification. The existing Rust implementations and host bindings are the starting point. [Valuation decisions](../decisions/financial/statements-analytics-valuation/README.md) · [Credit decisions](../decisions/financial/statements-analytics-credit/README.md) · [Follow-up register](../decisions/financial/FOLLOW_UPS.md#statements-analytics-valuation-comparisons-and-templates)

Slices with satisfied dependencies can proceed independently. Within a slice, follow the order of the implementation items. Verify upstream prerequisites against live owners. If an accepted upstream behavior is missing, land the smallest owner-side change and its tests before the dependent consumer. This applies in particular to dated capital fields in slices 3, 5 and 8, the covenant handoff in slice 6, and the pricing contract in slice 7. Use the accepted contracts at those boundaries to scope the work.

1. Run `mise run rust-lint-crate -- <package>` and scoped tests for every touched Rust crate. Use `mise run rust-test-integration -- <package> <target>` or `mise run rust-test-filter -- <package> <filter>` while iterating, and `mise run rust-test-crate -- <package>` for crate-wide changes. Analytics integration tests named below are modules of the `statements_analytics` target in package `finstack-quant-statements-analytics`. For example, run `mise run rust-test-filter -- finstack-quant-statements-analytics analysis_ecl --integration statements_analytics`. 2. Qualify each decision with independently calculated expected values, hand-built calendar cases or explicit state-transition tables as appropriate. Pin tolerances and units to the applicable accepted contract or fixture, and assert both values and eligibility states. Include unavailable and incomplete rows, typed zero, invalid inputs and provenance where the contract distinguishes them. Existing regression goldens remain useful for detecting changes.
3. Ship each public change through the normal Rust, Python and WASM entry points in its slice. Update stubs and runtime documentation, JSDoc, exports, schema and the parity ledger as applicable. Replace superseded paths and update callers, examples and affected UI fixtures in the same slice. Run `mise run gen-write` after a wire, generator, binding or facade change. Run focused Python tests with `mise run python-test-file -- <file-or-node-id>` against the rebuilt extension and `mise run wasm-test` for binding changes. Compare the same independent fixtures through each affected host, including wire round trips and error mapping. 4. Run `mise run slice-gate` before committing each slice. Record the verification and update the decision status and follow-up entry when the full behavior and independent qualification are complete. Run `mise run all` once after the slices pass. For institutional policies or sourced market inputs, retain the supplied provenance and document any empirical qualification still pending.
